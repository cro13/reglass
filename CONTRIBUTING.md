# Contributing to ReGlass

Thanks for helping. ReGlass is a developer-oriented iOS app tested on one pair of Ray-Ban Meta glasses. Bug
reports, test results from other glasses, connectors and fixes are all welcome.

By contributing, you agree that your work is licensed under the AGPL-3.0, like the rest of ReGlass
([LICENSE](LICENSE)).

## Before you start

- **Open an issue first** for anything bigger than a small fix, so we can agree on the approach.
- **Read the docs for the part you touch:**
  - [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): the modules and how a voice turn flows.
  - [ReGlassKit/DESIGN.md](ReGlassKit/DESIGN.md): the glasses engine's rules. What goes over the wire, or to Meta,
    doesn't change without evidence from real glasses.
  - [docs/CONNECTORS.md](docs/CONNECTORS.md): how to write a connector.
  - [docs/DESIGN.md](docs/DESIGN.md): the look and the copy.
  - [docs/GLASSES.md](docs/GLASSES.md): what's proven and what isn't.

## Building

- Setup and building: [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md).
- You need Xcode 27 or newer. Open `ReGlass.xcodeproj`.
- For your own iPhone, copy `Local.xcconfig.example` to `Local.xcconfig` and set your team and bundle ID.
- Meta sign-in needs the client tokens in `Secrets.xcconfig` and the generated sign-in function table.
  Both files are optional at build time. [Generate the local sign-in files](docs/META-CREDENTIALS.md)
- The project is generated by XcodeGen from `project.yml`. After you add, move or remove files, or change
  `project.yml`, run `xcodegen generate` and commit the updated `ReGlass.xcodeproj` with your change.
- Run the same offline checks as GitHub Actions on macOS with Xcode command-line tools.
  - `python3 tools/assistant/test_addressing.py`
  - `python3 tools/factory-wake-word/test_factory_download.py`
  - `python3 tools/meta-tokens/test_extract_meta_tokens.py`

  The first two compile the relevant Swift files directly with `swiftc`. All three run without service credentials.
  A full app build can be added to CI when GitHub's hosted runners have Xcode 27.

## Style

**Copy.** Plain words, short sentences. Say what happens, in the user's terms. The app is "ReGlass", pronounced "ree-glass"; the voice is "the
assistant's voice". No jargon on screen. More in [docs/DESIGN.md](docs/DESIGN.md).

**Colours.** Use the tokens in `ReGlass/Design/Theme.swift` (`Theme.accent`, `Theme.accentFill`,
`Theme.textSecondary` and the rest), never literal colours. Colour is never the only signal: pair it with words or a
symbol.

**Motion.** Every animation needs a Reduce Motion fallback: a short fade, or no animation where the change is only
movement. Read `accessibilityReduceMotion` and use the springs in `Theme.Motion`.

**Accessibility.** Support Dynamic Type (layouts stack at accessibility sizes) and VoiceOver (labels and hints on
anything custom).

**Swift.** Follow the Swift API Design Guidelines and the existing code. Short doc comments that say why. Small files,
one main type each. Swift concurrency; no blocking waits.

**Logs.** Keep logs to diagnostic details like states, counts, sizes and timings. Use short device identifiers only
where needed. Keep transcripts, replies, notes, titles, keys, tokens, full serial numbers and audio out of logs.

## Never commit

- `Secrets.xcconfig` or `Local.xcconfig`. Both are git-ignored; keep it that way.
- The generated `bloks-functions.txt` sign-in table. Keep it in the git-ignored package resources.
- Meta code, binaries, firmware, models, credentials or tokens.
- API keys, Meta account details, serial numbers, or logs with personal data.
- Recordings of anyone's voice, including your own, unless the change is about a public test file with a clear
  licence.

If you commit one by mistake, don't just delete it in a new commit: it stays in the history. Tell us, and rotate any key
that was exposed. See [SECURITY.md](SECURITY.md).

## Test on real glasses

ReGlass talks to real hardware, and the Simulator can't stand in for the glasses. Before you open a pull request:

- Try your change on real glasses, with ReGlass as their owner.
- **Say which model and firmware** you tested on (Settings → About these glasses), and your iPhone model and iOS
  version.
- Say what you tried, and what you couldn't test.
- If your change affects what the glasses can do, update the status in [docs/GLASSES.md](docs/GLASSES.md). Mark it
  **Proven** only when it works on real hardware.
- Results from glasses other than the Clubmaster (Audio) are especially welcome. See
  [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).

## Pull requests

- One topic per pull request, with a clear description of what changed and why.
- Update the docs that describe what you changed.
- New dependencies need a good reason. Add them, with their licence, to [THIRD_PARTY.md](THIRD_PARTY.md).
- Security problems don't go in issues or pull requests. See [SECURITY.md](SECURITY.md).
